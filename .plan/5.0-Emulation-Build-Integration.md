## 5.0.1 Executive Summary

This document defines how the kernel emulation framework integrates with FreeBSD's build and release processes — `buildworld`, `buildkernel`, `release`, `universe`, `native-xtools`, and `checkworld`. The emulator serves a dual role:

1. **Build target**: The emulator itself is built as part of the FreeBSD source tree (kernel modules + userland tooling), controlled by the `MK_EMULATION` build option (default: off).
2. **Build artifact tester**: The emulator can boot and test the artifacts produced by `buildworld`/`buildkernel` — kernels, kernel modules, and userland — inside isolated emulated environments, without requiring physical hardware for the target architecture.

**Key design decisions:**
- **Off by default**: `MK_EMULATION=no` — no emulation code is built unless explicitly enabled via `/etc/src.conf` (`WITH_EMULATION=yes`) or make command line (`MK_EMULATION=yes`).
- **No impact on existing builds**: When `MK_EMULATION=no` (the default), the build system is completely unaffected — no new directories, no new modules, no new targets.
- **Dual integration**: The emulator integrates at two levels — as a build target (what gets built) and as a test tool (what tests the build output).
- **Leverages existing infrastructure**: Builds on `native-xtools` for cross-toolchain, `universe` for multi-arch, and `checkworld`/Kyua for test execution.
- **Build artifact testing**: After `buildworld`/`buildkernel` completes, the emulator can boot the newly built kernel and userland inside an emulated instance, load test modules, and run the test suite — all without rebooting the host.

## 5.0.2 Build System Integration Points

### 5.0.2.1 Build Option: `MK_EMULATION`

The `MK_EMULATION` build option controls whether the emulation framework is built as part of `make buildworld` / `make buildkernel`.

**Option registration:**

| File | Change | Purpose |
|------|--------|---------|
| `share/mk/bsd.opts.mk` | Add `EMULATION` to `__DEFAULT_NO_OPTIONS` | Default off for all builds |
| `share/mk/src.opts.mk` | Register `EMULATION` in `__DEFAULT_NO_OPTIONS` | Make visible in `make showconfig` |
| `share/mk/src.opts.mk` | Add `EMULATION` to `BROKEN_OPTIONS` for non-FreeBSD hosts | Only buildable on FreeBSD |

**Effect on build targets:**

| Target | `MK_EMULATION=no` (default) | `MK_EMULATION=yes` |
|--------|---------------------------|-------------------|
| `buildworld` | No emulation code built | `usr.sbin/emu/` built as part of world |
| `buildkernel` | No emulation modules built | `emu.ko`, `emu_core.ko`, `emu_<arch>.ko` built |
| `modules` | No emulation modules | All emulation modules built |
| `release` | No emulation in release images | Emulation tools included in release |
| `universe` | No emulation for any arch | Emulation built for each arch in universe |
| `native-xtools` | No emulation in NXB set | `emu` tool included in NXB set |

### 5.0.2.2 Build Order & Dependencies

The emulation framework has specific build order requirements within the FreeBSD build system:

```
buildworld order:
  bootstrap-tools → legacy → build-tools → cross-tools → includes → libraries → everything
                                                                              └── usr.sbin/emu/ (MK_EMULATION=yes)

buildkernel order:
  config → cleandir → obj → kernel-tools → all
                                              └── sys/modules/emu_*/ (MK_EMULATION=yes)
```

**Dependency chain for emulation modules:**

```
emu.ko (master module)
  └── emu_core.ko (core framework)
        ├── emu_amd64.ko (amd64 CPU emulation)
        ├── emu_aarch64.ko (arm64 CPU emulation)
        ├── emu_arm.ko (arm 32-bit CPU emulation)
        ├── emu_i386.ko (i386 CPU emulation)
        ├── emu_powerpc.ko (powerpc CPU emulation)
        └── emu_riscv.ko (riscv CPU emulation)
```

**Build dependencies for `usr.sbin/emu/`:**

| Dependency | Purpose | Condition |
|------------|---------|-----------|
| `libvmmapi` | bhyve/VMM interaction | Always (bhyve path) |
| `libelf` | ELF parsing for kernel/module loading | Always |
| `libkvm` | Kernel memory access for stack capture | Always |
| `libutil` | `pty()` for console capture | Always |
| `libmd` | SHA-256 for blob verification | Always |
| `libssl` | TLS for blob downloads | `MK_EMULATION_BLOB_NET=yes` |
| `libarchive` | Archive extraction for blob management | Always |

### 5.0.2.3 Integration with `sys/modules/Makefile`

The emulation modules are added to the kernel module build system:

```makefile
# In sys/modules/Makefile:
.if ${MK_EMULATION} != "no"
SUBDIR+=	emu_core
. if ${MACHINE_CPUARCH} == "amd64"
SUBDIR+=	emu_amd64
SUBDIR+=	emu_i386
. endif
. if ${MACHINE_CPUARCH} == "aarch64"
SUBDIR+=	emu_aarch64
. endif
. if ${MACHINE_CPUARCH} == "arm"
SUBDIR+=	emu_arm
. endif
. if ${MACHINE_CPUARCH} == "powerpc"
SUBDIR+=	emu_powerpc
. endif
. if ${MACHINE_CPUARCH} == "riscv"
SUBDIR+=	emu_riscv
. endif
SUBDIR+=	emu  # master module (always last)
.endif
```

**Key rule:** Architecture-specific modules are only built when the host CPUARCH matches, because they contain native instruction decoders that are compiled for the host architecture. Cross-architecture emulation modules (e.g., building `emu_arm64.ko` on an amd64 host) are NOT built during `buildkernel` — they are built as userland components in `usr.sbin/emu/`.

### 5.0.2.4 Integration with `usr.sbin/Makefile`

```makefile
# In usr.sbin/Makefile:
.if ${MK_EMULATION} != "no"
SUBDIR+=	emu
.endif
```

Per-architecture `usr.sbin/Makefile.*` files include the emulation frontends:

```makefile
# In usr.sbin/Makefile.amd64:
.if ${MK_EMULATION} != "no"
SUBDIR+=	emu
.endif
```

## 5.0.3 Build Artifact Testing

### 5.0.3.1 Testing `buildkernel` Artifacts

After `make buildkernel KERNCONF=GENERIC` completes, the emulator can boot the newly built kernel and test it:

**Workflow:**

```
1. make buildkernel KERNCONF=GENERIC
   ↓
2. emu init --arch amd64 --name test-kernel
   (creates instance, downloads firmware blobs)
   ↓
3. emu start --name test-kernel \
     --kernel /usr/obj/usr/src/amd64.amd64/sys/GENERIC/kernel \
     --image /var/emu/images/freebsd-test.img
   (boots the newly built kernel in emulated environment)
   ↓
4. emu test --name test-kernel --test /usr/src/tests/sys/kern/
   (runs kernel test suite inside emulated instance)
   ↓
5. emu stop --name test-kernel
   (clean shutdown)
   ↓
6. emu destroy --name test-kernel
   (cleanup)
```

**Key features for kernel testing:**

| Feature | Implementation | Purpose |
|---------|---------------|---------|
| Direct kernel boot | `emu_boot_load()` loads ELF kernel directly | No need for full disk image |
| Initrd/initramfs | Ramdisk-based root filesystem | Minimal test environment |
| Module pre-loading | Load test modules at boot | Automated module testing |
| Console capture | `emu_console_write()` captures all output | Test result collection |
| Crash detection | `emu_crash_detect()` catches panics | Safe testing of crash-prone code |
| Snapshot/restore | `emu_snapshot_save/restore()` | Fast iteration without reboot |

### 5.0.3.2 Testing `buildworld` Artifacts

After `make buildworld` completes, the emulator can boot the newly built userland:

**Workflow:**

```
1. make buildworld
   ↓
2. make buildkernel KERNCONF=GENERIC
   ↓
3. emu init --arch amd64 --name test-world
   ↓
4. emu start --name test-world \
     --kernel /usr/obj/usr/src/amd64.amd64/sys/GENERIC/kernel \
     --userland /usr/obj/usr/src/amd64.amd64/ \
     --image /var/emu/images/freebsd-test.img
   (boots with newly built kernel AND userland)
   ↓
5. emu test --name test-world --test /usr/src/tests/
   (runs full test suite inside emulated instance)
   ↓
6. emu stop --name test-world
   emu destroy --name test-world
```

**Userland testing modes:**

| Mode | Description | Use Case |
|------|-------------|----------|
| `--userland` | Replace all userland binaries | Full world testing |
| `--userland-pkg` | Install userland as packages | pkgbase testing |
| `--userland-overlay` | Overlay specific binaries | Targeted testing |
| `--userland-nfs` | NFS-mount userland from host | Development iteration |

### 5.0.3.3 Testing Kernel Modules

The primary use case — testing kernel modules under development:

**Workflow:**

```
1. cd /home/user/kernel-module
   make
   ↓
2. emu init --arch amd64 --name test-module
   ↓
3. emu start --name test-module \
     --kernel /boot/kernel/kernel \
     --image /var/emu/images/freebsd-test.img
   ↓
4. emu load --name test-module \
     --module /home/user/kernel-module/my_module.ko
   (loads module into running emulated instance)
   ↓
5. emu test --name test-module \
     --test /home/user/kernel-module/tests/
   (runs module-specific tests)
   ↓
6. emu stack --name test-module
   (capture kernel stacks to verify module behavior)
   ↓
7. emu unload --name test-module --module my_module
   (unload module, verify cleanup)
   ↓
8. emu stop --name test-module
   emu destroy --name test-module
```

**Cross-architecture module testing:**

```
# Build module for arm64 on amd64 host
make CROSS_TOOLCHAIN=aarch64-freebsd-gcc13

# Test in arm64 emulator
emu init --arch arm64 --name test-arm64-module
emu start --name test-arm64-module \
  --kernel /usr/obj/arm64.aarch64/sys/GENERIC/kernel \
  --image /var/emu/images/freebsd-arm64-test.img
emu load --name test-arm64-module \
  --module ./my_module.ko  # arm64 binary
emu test --name test-arm64-module --test ./tests/
emu stop --name test-arm64-module
emu destroy --name test-arm64-module
```

## 5.0.4 Release Process Integration

### 5.0.4.1 Integration with `make release`

When `MK_EMULATION=yes`, the emulation framework is included in release media:

**What gets included in release:**

| Component | Location in Release | Condition |
|-----------|-------------------|-----------|
| `emu.ko` (master module) | `/boot/kernel/emu.ko` | `MK_EMULATION=yes` |
| `emu_core.ko` | `/boot/kernel/emu_core.ko` | `MK_EMULATION=yes` |
| `emu_<arch>.ko` modules | `/boot/kernel/emu_*.ko` | `MK_EMULATION=yes` + host arch match |
| `emu` userland tool | `/usr/sbin/emu` | `MK_EMULATION=yes` |
| `emu.8` man page | `/usr/share/man/man8/emu.8` | `MK_EMULATION=yes` |
| `emu.conf.5` man page | `/usr/share/man/man5/emu.conf.5` | `MK_EMULATION=yes` |
| `emulation.4` man page | `/usr/share/man/man4/emulation.4` | `MK_EMULATION=yes` |
| Test suite | `/usr/tests/usr.sbin/emu/` | `MK_TESTS=yes` + `MK_EMULATION=yes` |

**Release Makefile changes:**

```makefile
# In release/Makefile, base.txz target:
.if ${MK_EMULATION} != "no"
# emu kernel modules are included in kernel.txz automatically
# emu userland tool is included in base.txz automatically
# No special handling needed — standard build system integration
.endif
```

**Release media types:**

| Media | Emulation Support | Notes |
|-------|------------------|-------|
| `disc1.iso` | ✅ Included | `emu` tool + modules on install media |
| `dvd1.iso` | ✅ Included | Same as disc1 |
| `memstick.img` | ✅ Included | `emu` tool + modules on USB install |
| `mini-memstick.img` | ❌ Not included | Minimal image, no emulation |
| VM images | ✅ Included | `emu` pre-installed in VM images |
| Cloud images | ✅ Included | `emu` pre-installed in cloud images |
| `native-xtools` | ✅ Included | `emu` in NXB set for cross-build hosts |

### 5.0.4.2 Release Artifact Testing

The emulator can be used to test release artifacts before distribution:

**Release testing workflow:**

```
1. make release
   ↓
2. # Test the release kernel
   emu init --arch amd64 --name test-release-kernel
   emu start --name test-release-kernel \
     --kernel release/dist/kernel.txz  \
     --image /var/emu/images/freebsd-test.img
   emu test --name test-release-kernel --test /usr/src/tests/sys/
   emu stop --name test-release-kernel
   emu destroy --name test-release-kernel
   ↓
3. # Test the release userland
   emu init --arch amd64 --name test-release-world
   emu start --name test-release-world \
     --kernel release/dist/kernel.txz \
     --userland release/dist/base.txz \
     --image /var/emu/images/freebsd-test.img
   emu test --name test-release-world --test /usr/src/tests/
   emu stop --name test-release-world
   emu destroy --name test-release-world
   ↓
4. # Test cross-architecture release artifacts
   for arch in arm64 riscv64; do
     emu init --arch $arch --name test-release-$arch
     emu start --name test-release-$arch \
       --kernel release/dist/$arch/kernel.txz
     emu test --name test-release-$arch --test /usr/src/tests/sys/
     emu stop --name test-release-$arch
     emu destroy --name test-release-$arch
   done
```

**Release validation targets:**

| Target | Description | Default |
|--------|-------------|---------|
| `make release-test` | Test all release artifacts in emulator | Off (requires `MK_EMULATION=yes`) |
| `make release-test-kernel` | Test kernel.txz only | Off |
| `make release-test-world` | Test base.txz only | Off |
| `make release-test-archs` | Test all architecture artifacts | Off |

```makefile
# In release/Makefile:
.if ${MK_EMULATION} != "no"
release-test: release-test-kernel release-test-world .PHONY
release-test-kernel: kernel.txz .PHONY
	@echo "Testing kernel.txz in emulator..."
	emu init --arch ${TARGET_ARCH} --name release-test-kernel
	emu start --name release-test-kernel \
	    --kernel ${.OBJDIR}/kernel.txz
	emu test --name release-test-kernel \
	    --test ${WORLDDIR}/tests/sys/
	emu stop --name release-test-kernel
	emu destroy --name release-test-kernel
	@echo "Kernel release test PASSED"
release-test-world: base.txz .PHONY
	@echo "Testing base.txz in emulator..."
	emu init --arch ${TARGET_ARCH} --name release-test-world
	emu start --name release-test-world \
	    --kernel ${.OBJDIR}/kernel.txz \
	    --userland ${.OBJDIR}/base.txz
	emu test --name release-test-world \
	    --test ${WORLDDIR}/tests/
	emu stop --name release-test-world
	emu destroy --name release-test-world
	@echo "World release test PASSED"
.endif
```

## 5.0.5 Integration with `make universe`

### 5.0.5.1 Universe Build + Test

The `universe` target builds world and kernel for all supported architectures. With `MK_EMULATION=yes`, it can also test each architecture's build artifacts:

**Extended universe workflow:**

```
make universe MK_EMULATION=yes WITH_EMULATION_TEST=yes
```

This triggers:
1. Build world+kernel for each architecture (existing behavior)
2. After each architecture's build completes, boot the kernel in the emulator
3. Run a smoke test suite inside the emulated environment
4. Report pass/fail for each architecture

**Universe test targets:**

```makefile
# In Makefile (conceptual):
.if ${MK_EMULATION} != "no" && defined(WITH_EMULATION_TEST)
universe_${target}_test: universe_${target} .PHONY
	@echo ">> Testing ${target} build in emulator..."
	emu init --arch ${target_arch} --name universe-test-${target}
	emu start --name universe-test-${target} \
	    --kernel ${KRNLOBJDIR}/${target}/GENERIC/kernel
	emu test --name universe-test-${target} \
	    --test ${.CURDIR}/tests/sys/kern/emulation_smoke/
	emu stop --name universe-test-${target}
	emu destroy --name universe-test-${target}
	@echo ">> ${target} emulation test PASSED"
.endif
```

**Universe test modes:**

| Mode | Variable | Description |
|------|----------|-------------|
| Smoke test | `WITH_EMULATION_TEST=yes` | Quick boot + basic sanity checks |
| Full test | `WITH_EMULATION_TEST=full` | Boot + run full test suite |
| Module test | `WITH_EMULATION_TEST=modules` | Boot + load all built modules |
| Cross-arch | `WITH_EMULATION_TEST=cross` | Test cross-arch builds in emulator |

### 5.0.5.2 Tinderbox Integration

The `tinderbox` target (universe with failure tracking) integrates naturally:

```
make tinderbox MK_EMULATION=yes WITH_EMULATION_TEST=yes
```

If an architecture's kernel builds but fails to boot in the emulator, it's reported as a failure:

```
>> amd64 build PASSED
>> amd64 emulation test PASSED
>> arm64 build PASSED
>> arm64 emulation test FAILED (kernel panic at boot)
>> riscv64 build PASSED
>> riscv64 emulation test PASSED
>> i386 build PASSED
>> i386 emulation test PASSED
*** Failed targets:
    arm64 — emulation test failed
```

## 5.0.6 Integration with `native-xtools`

### 5.0.6.1 Emulator in NXB Set

The `native-xtools` target builds a set of static binaries for use in QEMU user-mode jails (used by Poudriere for cross-building ports). When `MK_EMULATION=yes`, the `emu` tool is included in the NXB set:

```makefile
# In Makefile.inc1, NXBDIRS:
.if ${MK_EMULATION} != "no"
NXBDIRS+=	usr.sbin/emu
.endif
```

**Why include `emu` in NXB:**

| Reason | Description |
|--------|-------------|
| Cross-build testing | Test ports built for target arch inside emulator |
| Package validation | Validate packages before installation |
| CI/CD for ports | Automated testing of cross-built packages |
| Developer workflow | Test cross-built software without target hardware |

### 5.0.6.2 NXB + Emulator Workflow

```
# On amd64 host, build native-xtools for arm64
make native-xtools NXB_TARGET=arm64 NXB_TARGET_ARCH=aarch64 \
    MK_EMULATION=yes

# Install NXB set
make native-xtools-install DESTDIR=/nxb-bin

# Use emu from NXB set to test arm64 binaries
/nxb-bin/usr/sbin/emu init --arch arm64 --name test-nxb
/nxb-bin/usr/sbin/emu start --name test-nxb \
    --kernel /usr/obj/arm64.aarch64/sys/GENERIC/kernel
/nxb-bin/usr/sbin/emu load --name test-nxb \
    --module /usr/ports/work/arm64/my-port.so
/nxb-bin/usr/sbin/emu test --name test-nxb \
    --test /usr/ports/work/arm64/tests/
/nxb-bin/usr/sbin/emu stop --name test-nxb
```

### 5.0.7.3 Build Artifact Test Definitions

Each build artifact test verifies that a specific build output works correctly inside the emulator:

| Test ID | Test Name | Artifact Tested | What It Verifies |
|---------|-----------|-----------------|------------------|
| BA.1 | `build_kernel_boot` | `kernel` (buildkernel output) | Kernel boots to mountroot prompt |
| BA.2 | `build_kernel_modules` | Kernel modules | All built modules load successfully |
| BA.3 | `build_kernel_crash` | Kernel with crash module | Crash is detected, dump captured |
| BA.4 | `build_world_userland` | Userland binaries | Basic commands work (ls, ps, etc.) |
| BA.5 | `build_world_libraries` | Shared libraries | Library loading works |
| BA.6 | `build_world_tests` | Test suite | Kyua tests pass inside emulator |
| BA.7 | `release_kernel_txz` | `kernel.txz` | Release kernel boots |
| BA.8 | `release_base_txz` | `base.txz` | Release userland works |
| BA.9 | `cross_arch_kernel` | Cross-compiled kernel | Non-native kernel boots in emulator |
| BA.10 | `cross_arch_module` | Cross-compiled module | Non-native module loads and works |
| BA.11 | `universe_smoke` | All universe kernels | Each arch kernel boots in emulator |
| BA.12 | `nxb_emu_tool` | `emu` from NXB set | Emu tool works in cross-build environment |

**Detailed test specification for BA.1 (build_kernel_boot):**

```
Test: build_kernel_boot
Purpose: Verify that a kernel built by buildkernel boots in the emulator
Artifact: /usr/obj/usr/src/<arch>.<arch>/sys/GENERIC/kernel

Steps:
  1. Check that kernel file exists
  2. emu init --arch <arch> --name test-ba1
  3. emu start --name test-ba1 --kernel <kernel_path>
     Expected: emu start returns 0, instance status is "running"
  4. Wait up to 30 seconds for kernel boot messages
     Expected: Console contains "FreeBSD" and "mountroot" or "init"
  5. emu console --name test-ba1 --dump
     Expected: Output contains "FreeBSD <version>"
  6. emu stop --name test-ba1
     Expected: emu stop returns 0
  7. emu destroy --name test-ba1
     Expected: emu destroy returns 0

Failure modes:
  - Kernel file not found: Test SKIP (buildkernel not run)
  - emu start fails: Test FAIL (emulator or kernel issue)
  - No boot messages after 30s: Test FAIL (kernel hang)
  - Console shows panic: Test FAIL (kernel panic at boot)
  - emu stop fails: Test FAIL (instance stuck)
```

**Detailed test specification for BA.9 (cross_arch_kernel):**

```
Test: cross_arch_kernel
Purpose: Verify that a cross-compiled kernel boots in the emulator
Artifact: /usr/obj/<target_arch>.<target_arch>/sys/GENERIC/kernel

Prerequisites:
  - CROSS_TOOLCHAIN must be installed for target architecture
  - buildkernel must have been run for target architecture

Steps:
  1. Check that cross-compiled kernel file exists
  2. emu init --arch <target_arch> --name test-ba9
  3. emu start --name test-ba9 --kernel <cross_kernel_path>
     Expected: emu start returns 0
  4. Wait up to 60 seconds for kernel boot messages
     Expected: Console contains architecture-specific boot messages
  5. emu console --name test-ba9 --dump
     Expected: Output confirms target architecture
  6. emu stop --name test-ba9
  7. emu destroy --name test-ba9

Failure modes:
  - Cross-compiled kernel not found: Test SKIP
  - Emulator doesn't support target arch: Test SKIP
  - Kernel fails to boot: Test FAIL (cross-compilation issue)
  - Architecture mismatch in boot messages: Test FAIL
```

## 5.0.8 CI/CD Integration

### 5.0.8.1 GitHub Actions Integration

The emulator enables CI/CD pipelines that test kernel modules and build artifacts without requiring physical hardware:

```yaml
# .github/workflows/kernel-test.yml
name: Kernel Module Test
on: [push, pull_request]

jobs:
  build-and-test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      
      - name: Build kernel with emulation
        run: |
          make buildworld MK_EMULATION=yes
          make buildkernel MK_EMULATION=yes
      
      - name: Test kernel in emulator
        run: |
          kldload emu.ko
          emu init --arch amd64 --name ci-test
          emu start --name ci-test \
            --kernel /usr/obj/amd64.amd64/sys/GENERIC/kernel
          emu test --name ci-test --test tests/sys/kern/
          emu stop --name ci-test
          emu destroy --name ci-test
      
      - name: Cross-arch test
        run: |
          emu init --arch arm64 --name ci-arm64-test
          emu start --name ci-arm64-test \
```

## 5.0.10 Smoke Test Suite for Build Artifacts

### 5.0.10.1 Smoke Test Definition

The smoke test suite (`tests/sys/kern/emulation_smoke/`) is a minimal set of tests that verify a kernel boots and is functional inside the emulator:

| Test | What It Checks | Expected Result |
|------|---------------|-----------------|
| `boot_test` | Kernel boots to mountroot prompt | Console contains "mountroot" or "init" |
| `version_test` | `uname -a` returns correct version | Output matches build version |
| `module_test` | `kldstat` lists expected modules | At least kernel module loaded |
| `cpu_test` | `sysctl hw.model` returns CPU info | Non-empty CPU model string |
| `memory_test` | `sysctl hw.physmem` returns memory | Memory > 0 |
| `panic_test` | Trigger panic, verify crash dump | Crash detected, dump captured |
| `reboot_test` | `shutdown -r now` triggers reboot | Instance restarts cleanly |

### 5.0.10.2 Smoke Test Script

```sh
#!/bin/sh
# tests/sys/kern/emulation_smoke/boot_test.sh
# SPDX-License-Identifier: BSD-3-Clause

# Test: Kernel boots to mountroot prompt
# Artifact: Kernel built by buildkernel

# Check if emu is available
if ! which emu >/dev/null 2>&1; then
    echo "SKIP: emu not available"
    exit 0
fi

# Check if kernel exists
KERNEL="${KERNEL_PATH:-/boot/kernel/kernel}"
if [ ! -f "$KERNEL" ]; then
    echo "SKIP: kernel not found at $KERNEL"
    exit 0
fi

# Initialize instance
INSTANCE_NAME="smoke-boot-$$"
emu init --arch "${TARGET_ARCH:-amd64}" --name "$INSTANCE_NAME" 2>&1
if [ $? -ne 0 ]; then
    echo "FAIL: emu init failed"
    exit 1
fi

# Start instance
emu start --name "$INSTANCE_NAME" --kernel "$KERNEL" 2>&1
if [ $? -ne 0 ]; then
    echo "FAIL: emu start failed"
    emu destroy --name "$INSTANCE_NAME" 2>/dev/null
    exit 1
fi

# Wait for boot messages
sleep 10

# Check console output
CONSOLE=$(emu console --name "$INSTANCE_NAME" --dump 2>&1)
if echo "$CONSOLE" | grep -q "FreeBSD"; then
    echo "PASS: Kernel booted successfully"
    echo "  Boot messages contain 'FreeBSD'"
else
    echo "FAIL: Kernel did not boot"
    echo "  Console output:"
    echo "$CONSOLE" | tail -20
    emu stop --name "$INSTANCE_NAME" --force 2>/dev/null
    emu destroy --name "$INSTANCE_NAME" 2>/dev/null
    exit 1
fi

# Cleanup
emu stop --name "$INSTANCE_NAME" 2>/dev/null
emu destroy --name "$INSTANCE_NAME" 2>/dev/null
exit 0
```

## 5.0.13 Risks & Mitigations

| Risk | Impact | Likelihood | Mitigation |
|------|--------|------------|------------|
| `MK_EMULATION=yes` increases build time | Medium | High | Only affects opt-in builds; default off |
| Build artifact tests are slow | Medium | Medium | Use bhyve path when available; parallelize per-arch tests |
| Cross-arch emulation is slow | High | Medium | Use for smoke tests only; full tests use native hardware |
| Release testing adds release build time | Medium | Low | Off by default; separate `release-test` target |
| Emulator bugs cause false build failures | High | Medium | Separate build success from test success; clear error reporting |
| Universe test failures block CI | Medium | Low | Non-failing by default; configurable failure mode |
| NXB emu tool doesn't work in QEMU jail | Medium | Low | Static build; test in QEMU user-mode before release |
| Build artifact auto-detection finds wrong kernel | Medium | Low | Explicit `--kernel` flag overrides auto-detection |
| Release media size increases with emulation | Low | Low | Emulation components are small (< 5 MB total) |
| Test flakiness from timing-dependent checks | Medium | Medium | Configurable timeouts; retry logic for transient failures |

## 5.0.16 Conclusion

The emulation framework's integration with FreeBSD's build and release processes provides a powerful, opt-in capability for testing build artifacts without physical hardware. Key takeaways:

- **Off by default**: `MK_EMULATION=no` ensures zero impact on existing builds. Users explicitly opt in via `/etc/src.conf` or make command line.
- **Dual role**: The emulator is both a build target (what gets built) and a test tool (what tests the build output).
- **Leverages existing infrastructure**: Builds on `native-xtools`, `universe`, `checkworld`, and Kyua — no new build system paradigms.
- **Comprehensive testing**: From individual kernel module testing to full universe validation, the emulator provides a consistent test environment across all architectures.
- **CI/CD ready**: Templates for GitHub Actions, Jenkins, and Poudriere make it easy to integrate into existing workflows.
- **Release validation**: The `release-test` target ensures release artifacts are functional before distribution.
- **Incremental adoption**: Start with amd64 (bhyve, fast), add cross-architecture testing over time (emulator, slower but comprehensive).

This integration transforms FreeBSD's build system from a "build and hope it works" process into a "build, test, and verify" process — all without requiring a rack of physical hardware for every supported architecture.
