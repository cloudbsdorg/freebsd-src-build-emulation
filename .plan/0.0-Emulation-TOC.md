## File Naming Convention

Files follow the pattern: `<Major>.<Minor>-MainTopic-SubTopic[-subsubtopic].md`

- `<Major>.<Minor>` — Hierarchical numbering for ordering (e.g., `1.0`, `1.1`, `2.0`)
- `MainTopic` — Primary topic (e.g., `Emulation`, `Arch`)
- `SubTopic` — Secondary topic (e.g., `Security`, `Devices`, `Blob`)
- `-subsubtopic` — Optional further refinement (e.g., `p1-ThreatModel-Isolation`)

**Numbering scheme:**
- `0.x` — Meta-documents (TOC, workflow, guidelines)
- `1.x` — Core emulation framework (overview + security)
- `2.x` — Architecture specifications
- `3.x` — Device emulation
- `4.x` — Supporting infrastructure (blobs, CPU models)
- `5.x` — Build & release integration

---

## Section Numbering Convention

Within each document, sections follow the pattern: `<Major>.<Minor>.<Section>[.<Subsection>[.<and so on>]]

- The document prefix (`<Major>.<Minor>`) matches the file number
- Sections are numbered sequentially within each document
- Subsections extend the hierarchy as needed

**Example:** In document `1.0-Emulation-Overview.md`:
- `1.0.1` Executive Summary
- `1.0.2` Motivation & Problem Statement
- `1.0.2.1` Why Emulation?
- `1.0.2.2` Why Not Just bhyve?

In document `1.1-Emulation-Security-p1-ThreatModel-Isolation.md`:
- `1.1.1` Executive Summary
- `1.1.2` Threat Model
- `1.1.2.1` Assets to Protect
